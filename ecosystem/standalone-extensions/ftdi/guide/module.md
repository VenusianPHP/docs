# Module

Scope, file layout, libftdi1/libusb linkage, undeclared libftdi exports, ZTS cache, class registration.

## Scope

libftdi1 bindings, 1:1, plain C on Zend API. No Zephir, no FFI. Global functions under libftdi's names (four spelt as `microscrap/ftdi` exported them: `ftdi_tci_flush`, `ftdi_tco_flush`, `ftdi_tcio_flush`, `ftdi_read_chip_id`). No policy: no MPSSE helpers, no event loop, no throwing on negative libftdi codes. Linux + macOS; Windows excluded in `composer.json` `php-ext`.

## Files

| File | Holds |
|---|---|
| `ftdi.c` | objects, live-property handlers, every function, MINIT/RINIT/MINFO |
| `php_ftdi.h` | `PHP_FTDI_VERSION` |
| `ftdi.stub.php` | namespace `Ftdi` classes and enums, every function, every constant; source of `ftdi_arginfo.h` |
| `ftdi_arginfo.h` | generated by gen_stub; never hand-edited |
| `config.m4` | `PKG_CHECK_MODULES` libftdi1 ≥ 1.5, libusb-1.0 ≥ 1.0.16; flags into `FTDI_SHARED_LIBADD` |

libftdi1 floor 1.5: 1.4's `ftdi.h` lacks `ftdi_tciflush`/`ftdi_tcoflush`/`ftdi_tcioflush`, `ftdi_setflowctrl_xonxoff`, `SIO_TCIFLUSH`/`SIO_TCOFLUSH` and `AUTO_DETACH_REATACH_SIO_MODULE`, all bound. Installers check the same floor through `pkg-config --exists` before building. Debian trixie and Homebrew ship 1.5.

## Linkage

libusb linked directly: the binding calls `libusb_ref_device`/`libusb_unref_device`, `libusb_get_pollfds`, `libusb_get_next_timeout`, `libusb_handle_events_timeout_completed` on `ctx->usb_ctx`. Same libusb libftdi links, via pkg-config.[^config]

Two libftdi symbols are exported but absent from `ftdi.h`; `ftdi.c` declares them `extern`: `convert_baudrate_UT_export()` (baud divisor maths, exported for libftdi's unit tests) → `ftdi_convert_baudrate_ut_export()`; `set_ft232h_cbus()` → `ftdi_set_ft232h_cbus()`. Both exported by 1.5.[^ftdi-c]

## Lifecycle hooks

- MINIT: `ZEND_TSRMLS_CACHE_UPDATE()` under ZTS, `register_ftdi_symbols()` (constants), five classes, two enums. Context/device/transfer get custom `create_object`, `free_obj`, `clone_obj = NULL`, `offset`; context and transfer also get live-property handlers. See [objects](/docs/{{version}}/ecosystem/standalone-extensions/ftdi/api/objects).
- RINIT: `ZEND_TSRMLS_CACHE_UPDATE()` under ZTS. No GINIT exists, so without this a ZTS request thread reads `EG()` through a NULL cache and segfaults.
- MINFO: extension version and libftdi1 `version_str` (`php --ri ftdi`).
- No module globals, no RSHUTDOWN: all state hangs off objects.[^ftdi-c]

[^ftdi-c]: ftdi.c
[^config]: config.m4
